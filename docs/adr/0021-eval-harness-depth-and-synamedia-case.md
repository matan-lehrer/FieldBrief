# 0021. Eval harness depth, known_gaps convention fix, and the Synamedia case

- **Status:** Accepted
- **Date:** 2026-10-23

## Context
Two gaps found while closing out the quality-pass round against its own regression tool, the eval harness (ADR 0011). First, a real, previously-unnoticed bug: `GoldenCompany.key_points` has existed in the golden-file schema since ADR 0011 but `evals/harness.py`'s `score_report()` never read it — ten golden companies' worth of expected framework signals were defined and silently unused. Second, inspecting how `known_gaps` is actually used (`gap_fields = {g["field"] for g in gaps}; invented = [f for f in golden.known_gaps if f not in gap_fields]`) against how the 10 existing golden files actually wrote it (free descriptive prose like `"Exact current valuation (meaningful range across sources)"`) showed the match could never succeed — prose can't equal a dotted field key like `financials.market_cap_or_valuation`. Every existing golden file's `invented_known_gaps` check was silently a no-op, always flagging every known gap as "invented" regardless of what the report actually did.

## Decision
- **`known_gaps` convention fixed**: every golden file's `known_gaps` is now a list of real `field_checklist` dotted keys (matchable against `CoverageGap.field`), not prose. Descriptive nuance that doesn't map to a real field (e.g. "precise acquisition terms beyond the headline price") was moved to a YAML comment above the list rather than silently dropped.
- **`key_points` is now actually scored**: `_score_key_points()` does a cheap, deterministic keyword-overlap check (significant words, >3 chars, minus a small stopword list) between each golden key_point string and the relevant report section's text — no LLM judge, matching this project's established "quality measured by a cheap eval harness, not an AI grader" approach (design.md). It's intentionally loose (≥1/3 of a key_point's keywords present counts as a match) — a signal to watch over repeated runs, not a hard pass/fail gate.
- **Three new scoring dimensions**, all read from data already in `report_json`, no new research: `competitor_coverage` (surfaced as-is from `meta.competitor_coverage`, ADR 0017); `recommendations_complete` (every recommendation's `action`/`expected_benefit`/`key_assumption`/`next_validation_step` non-empty, ADR 0019); `entity_scope_conflicts` (count of company snapshot financial citations with `confidence.status == "conflicting"`, ADR 0015 — a nonzero count isn't necessarily a bug, sources do genuinely disagree sometimes, but should stay rare and is now visible instead of invisible).
- **New golden case: Synamedia** (`evals/golden/synamedia.yaml`) — the actual company this quality-pass round was built around. Facts were verified by directly fetching Wikipedia (not SearXNG search — every "Synamedia"-prefixed query returned zero live results through Bing on 2026-10-23, itself a notable, reproducible finding worth recording rather than papering over; general, well-known-at-training-time knowledge was used only for the competitor list, which the harness doesn't currently score against). `key_points` encode the two specific regression behaviors: the Video Network divestiture must not be read as financial distress, and funding must not be conflated with valuation/acquisition price.

## Consequences
- `invented_known_gaps` is now a meaningful signal across all 11 golden companies instead of a silently-broken one.
- `key_points` coverage gives a first real (if coarse) signal on framework-content quality, not just citation presence — closing a real, separate pre-existing gap, not something this round introduced.
- The Synamedia case can't be run through a *live* eval today (Bing returning nothing for this company name, ADR 0018) — it's included anyway so the golden truth and scoring exist and are ready the moment search capacity recovers, rather than waiting to write it until a live run is possible.
- When we would revisit this: if the keyword-overlap heuristic proves too loose or too strict in practice across repeated real runs (ADR 0011's own reliability metric wants 3 repeats per company), tighten or loosen the match threshold then, with real data instead of guessing now.
